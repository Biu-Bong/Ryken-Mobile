## 1. 固件包结构与身份


## 2. 协议检测的触发机制

### 2.1 用户操作路径（说明书 V1.2 · 第 5 页）

1. 应用页面 → 选择「协议」→ 单击「√」进入协议检测提示页
2. 按需设置：**模拟 E-Marker IN/OFF**（直插充电头开、带线测关）、**充电宝模式**、**自动检测 PE**（默认开）
3. 选择「**准备好了**」→ 进入自动检测
4. 完成后可单击协议查看详情 / PDO 报文，也可从详情页进入协议诱骗（触发）

**进入条件（门控）**：法拉电容低电量、或另一端口已接设备/有电流 → 无法进入检测。

### 2.2 固件里的检测流程（反汇编 + 字符串证据）

- 扫描动画：`Auto Check .` ~ `Auto Check ......`（@0x081F4E-0x08200F 连续 7 帧）
- PD 寻源：`Find PD Charge.` ~ `......`（@0x082078 / 0x0835077 区）
- 逐协议搜索（每协议一个独立搜索函数 + 对应状态文字，位于 0x08002D00-0x08003900 代码区）：

  | 协议 | "Search …" 字符串 | 引用代码 |
  | --- | --- | --- |
  | QC3+ | @0x08003D50 | 0x08003864 |
  | SVOOC | @0x08003CEC | 0x080032B8 |
  | TFCP | @0x08003D00 | 0x080033A4 |

- 搜索失败标记 `@Search Fail`；协议结果表：`PD3.0/PPS/AVS/EPR、QC…、SVOOC、UFCS、NUBIA、MIPPS、PVTPPS` 等

## 3. 离线记录的保存机制

### 3.1 文件命名与位置（固件字符串 + 保存代码双重确认）

- 文件名模板（固件 0x0800DAD4 起）：
  - `data/%02d_%dSec.bin` —— 短记录（秒级单位）
  - `data/%02d_%dms.bin` —— 长记录（毫秒单位，代码里有 ÷100 换算）
- 保存路径带盘符：`0:data/%s`（@0x0825FE）—— 即设备内部 4MB Flash 的 FAT 分区（RKX3 盘）
- 保存触发代码：0x0800DA46-0x0800DACE（组织文件名 → `sprintf` → FatFs 写入调用链），
  UI 侧对应字符串：`当前记录`、`记录功率 Recorded %.2fW`、`Saved %d`

### 3.2 记录控制项（说明书第 8/9 页 + 固件设置字符串）

| 设置 | 固件字符串 | 说明 |
| --- | --- | --- |
| 离线开始规则 | `OL-Start  OFF / >%.1fW` | 自动开始（功率大于阈值）或关 |
| 离线结束规则 | `OL-End    OFF / <%.1fW` | 自动结束 |
| 离线采样间隔 | `OLSI  %dSec / %dms` | 离线采样周期 |
| 实时采样间隔 | `RTSI  %dSec` | 实时曲线采样周期 |
| 离线记录时间 | `离线记录时间 %dSec/%dMin/%dHrs` | 单次记录时长（1mS-1800mS 等档位串也见到） |

- 容量：4MB Flash、**最多 10 组容量记录**（容量统计页），支持离线曲线回看（放大缩小）
- 曲线页按「√」键可设置：实时采样速度 / 离线采样速度 / 离线记录时长 / 开始规则 / 结束规则

> **待补**：`data/*.bin` 的**帧内格式**尚未逆出——需要从真机 U 盘里取一份记录文件样本
> 才能定字段（那时"手机读取离线记录"可以直接在 U 盘模式下抓文件解析）。

## 5. 上位机（PC 端）的数据保存

### 5.1 PC 上位机（RYKEN 0.5.4，Tauri）

- 主页「数据记录仪」实时记录（缓存深度可设），**文件**菜单：
  - `导出` → `.rdb`（**专有二进制格式**，与 CSV 同名成对；含 chartTitle / pollInterval / count / 统计）
  - `导出CSV` → `.csv`（导表用）
  - `导入` → 读回转台（importer.rs 可读记录 + PD/UFCS 协议数据）
- **真实 CSV 样例**（盘里现成：`X3 SE\RKX3SE\X3SE_原装_LDZM.csv`，2.9MB）：

```
time,voltage,current,power,cc1,cc2,dPlus,dMinus,temperature,phonePower,charge,energy,ed
00:00:00.000,6.965500,4.050200,28.211668,3.284000,0.000000,3.021000,3.236000,33,0.000000,0.000113,0.000784,0.0
```

  - `time` = 相对时间 HH:MM:SS.mmm；数值 6 位小数；`temperature` 整数；
  - `charge/energy` = 上位机对电流/功率的积分（同类含义），`ed` 列含义未定（样例恒 0.0）
- `.rdb`：头部非明文（疑似编码/加密），**手机端若要直接读 .rdb 需要再逆向**（样本：
  `X3SE_原装_LDZM.rdb` 7.4MB）

## 6. 怎么把电脑上位机的数据放到手机上看

按代价从低到高：

1. **手机 App 实现「导入记录」读 PC 的导出 CSV**（推荐）
   - PC 导出 CSV → 微信/QQ/数据线/网盘传到手机 → App 里「导入记录」选文件 → 解析重建曲线
   - 解析要点：表头列名映射 `voltage→vbus、current→ibus、power→pwr、dPlus→dp、dMinus→dm、
     temperature→temp、phonePower→batt?、charge→cap、energy→wh`；时间轴用 `HH:MM:SS.mmm` → ms；
     `charge/energy` 列直接用（或按积分重算）
   - 顺带修掉「导出记录」死按钮
2. **局域网直传**：PC 上继续用 `bridge.py` 那套（它自带 http server）——加一个"共享导出目录"，
   手机浏览器直接下载 CSV/rdb 文件
3. **USB 直连**：手机 OTG 读 PC？不现实（手机当 host 时 PC 是 host 角色互斥），走上面两条
4. `.rdb` 直读：**不建议作为第一步**，格式专有且未解码；CSV 是标准互通路径

> 设备 U 盘 `data/` 里的是**设备自己的二进制记录**，与 PC 的 CSV/rdb 是两套格式，不要混用。

## 7. 手机给功率表刷固件 + "自动开 U 盘模式"可行性

### 7.1 官方升级机制（已完全确认）

- **入口**：按住「返回」键，再插入数据线到 HID 口 → 电脑出现 **RKX3 + RKX3IAP 两个盘**
  （CC 线还需按住返回键再长按「-」键拿电；不识别时翻面试）
- **刷写**：把固件 `.bin` 复制进 **RKX3IAP 盘** → 等复制完成 → 设备自动刷写（升级完成后自动重新挂 U 盘）
- 设备侧：`FlashIAP.bin`（"Flash IAP V1.0"，含 `File Open Fail / %d%% / Update Success / 0:/RKX3.bin`）
  负责读盘→写 Flash→进度显示；主固件负责 IAP 模式界面（`0:main/iap.bmp` + 屏幕文字 `HID IAP`）
- PC 端自动化（官方 app 的做法，可直接借鉴）：
  - 盘符路径：`firmware.rs` —— 找盘(`FIND_DRIVE`/KX3IAP) → 等 `Ready.TXT` → 拷贝 →
    `CLEANING_BIN → UPGRADING → SUCCEED`（含文件名合法性/文件大小校验、失败重试）
  - 直连路径：`firmware_iap.rs` + `RYKEN_IAP.exe`（实为沁恒 WCH IAP v1.10 工具，走 CH375DLL，
    `ERASING → WRITING → VERIFYING → FINISHING`）——但同样要求"设备已进入 IAP 模式"

### 7.2 能否"手机 App 自动给表开 U 盘模式"？

**结论：不能（现有证据下）。**

- U 盘/IAP 模式是**设备上电时的按键判定**：返回键按住 → 进入 IAP 模式；否则普通 HID 模式。
  这是设备侧行为，手机无从代按。
- 固件里**没有找到**任何"软件切换进 U 盘模式"的命令：正常模式的 HID 命令集已被完整摸清
  （`INFO / START / KEEPALIVE` 三条，全部服务数据流），官方 PC 软件自己也必须让用户先按键插线。
- RYKEN_IAP.exe / PC 端 `firmware_iap.rs` 的报错原文都写着"请检查设备是否已进入 IAP 模式"——
  官方也没绕过这一步。

### 7.3 能实现的"最大自动化"（建议做成半自动刷机向导）

1. App 里先选好固件文件（从更新源检查版本、本地选文件）
2. 页面给出**唯一一个物理动作**指引：按住测试仪「返回」键 → 插入手机
3. App 监听 USB 存储卷出现（UsbManager + Storage Access Framework / StorageManager）
4. 自动识别 `RKX3IAP` 卷 → 自动把固件写入 → 监控写入完成 / 卷重枚举 → 提示升级完成
5. 兜底：若机型 SAF 对 OTG 卷只读，则引导用户用系统文件管理器粘贴（一次点击级）

**前置验证（需要真机+一台手机，5 分钟）**：
- 按住返回键把表插到手机上 → 系统文件管理器里能看到几个盘？`RKX3IAP` 能否写入？
- 能写 → 方案 3/4 直接可做；只读 → 用兜底方案

若要把"连按键都不用"做到底，**唯一途径是向厂商提固件需求**：在正常 HID 模式下接受一条
"重启进 IAP 模式"命令（固件里 IAP 模式代码齐备，加一条命令转发即可），新增该命令前一切
自动化都受限于物理按键。

## 9. 补充（2026-10-10 下午）：HID 帧协议层新发现

> 本节不属于固件包本体，是对设备↔主机通信帧的进一步解剖（依据历史抓包 1101 帧 + 官方文档）。

### 9.1 设备→主机帧里藏着 CRC16（新发现，1101/1101 帧 100% 通过）

- 算法与命令帧完全相同：**poly 0x2507 / init 0x11 / 结果 +1 / 不反转**，大端存储。
- 位置（相对同步头 0x55 的下标 i）：
  - **0x1A 信息帧**：CRC 覆盖 `i..i+23`（24 字节），存于 `i+24..i+25`
  - **0x1B 测量帧**：CRC 覆盖 `i..i+24`（25 字节），存于 `i+25..i+26`
- 用途：手机端解码器可以做帧完整性校验（坏帧直接丢），此前不知道。
- 实测：frames_live 501 + frames 400 + five_frames 200 = **1101 帧全通过**。

### 9.2 0x1B 测量帧尾部 37 字节已全部归类 —— 没有协议字段

```
[22..25] 00 00 00 00               （被 CRC 覆盖的收尾 4 字节）
[26..27] CRC16（大端，覆盖 [sync..sync+24]）
[28..29] 40 03                     常量
[30..32] 00 00 00
[33..34] u16（带载≈300、空载=0）   ← 内部遥测（非 V/I/协议）
[35..36] 00 00
[37..40] 0x0800EAC1                固件代码指针（常量）
[41..42] 同 [33..34]
[43..44] 00 00
[45..48] 0x0800EC83                固件代码指针（常量）
[49..52] 03 00 00 00
[53..56] 00 04 00 40
[57..60] 0x200048D0                RAM 指针（常量）
[61..62] u16（带载=23、空载=0）
[63] 00
[64] 序号（0..9 循环）
```

- 结论：**协议信息不在 0x1B 帧里**。协议数据走独立通道（见 9.3）。

### 9.3 协议数据的通道（下一步要抓的）
